# ИНСТРУКЦИЯ: от архива до работающего сайта на Render

Время: ~1,5 часа (из них ~40 минут — установка, если инструменты ещё не стоят).
Команды даны для Windows (PowerShell), macOS и Linux; где они различаются — это указано.

> **Честно о том, что проверено.** Проект написан по материалам уроков 1–9 (код практик взят за основу,
> дополнен деплоем). В среде, где он создавался, не было .NET SDK и интернета, поэтому **код не компилировался
> и не запускался**. Всё, что можно было сверить глазами (сигнатуры, пакеты, порядок middleware, конфигурация Render),
> сверено. Если на шаге 3–6 компилятор или тест выдаст ошибку — это нормальная часть работы: пришлите текст ошибки,
> и я исправлю файл. Не переписывайте код вслепую.

## Шаг 3. Запустить сервер локально

```bash
cd api
dotnet user-secrets set "Jwt:Key" "замените-на-свою-случайную-строку-не-короче-32-символов"
dotnet run
```

Ключ подписи токенов хранится вне проекта (user-secrets) и в git не попадёт.
Случайную строку можно получить так: macOS/Linux — `openssl rand -base64 48`;
PowerShell — `[Convert]::ToBase64String((1..48 | % { Get-Random -Max 256 }))`.

**Что должно получиться:** в консоли `Now listening on: http://localhost:5000`, терминал не возвращает приглашение
(это правильно). Откройте http://localhost:5000/swagger — виден список методов.
Откройте http://localhost:5000/api/listings?pageSize=6 — JSON с 6 объявлениями и `"total": 12`.

Локально используется SQLite: файл `api/listings.db` создаётся сам, начальные данные (8 районов, 12 объявлений) — тоже.

| Ошибка | Что делать |
|---|---|
| `OptionsValidationException … Jwt:Key` | Не задан ключ — повторите команду `user-secrets set` (≥ 32 символов). |
| `Address already in use` | Порт 5000 занят — остановите другой сервер (Ctrl+C) или запустите `dotnet run --urls http://localhost:5050` (и поменяйте порт в `web/src/environments/environment.ts`). |
| Ошибка восстановления пакета (`NU1102 … version`) | Пришлите полный текст ошибки: скорее всего, нужно уточнить версию одного пакета в `api/ListingsApi.csproj`. |

Остановите сервер (Ctrl+C) и вернитесь в корень: `cd ..`

## Шаг 5. Создать миграции базы (ВАЖНО сделать до первого деплоя)

На Render работает PostgreSQL, и по уроку 3 структуру базы ведут миграции. Создайте их один раз:

```bash
cd api
dotnet ef migrations add InitialCreate
cd ..
```

PostgreSQL для этого запускать **не нужно**: команда только описывает структуру, к базе не подключается.
Появится папка `api/Migrations` — она **обязательно** коммитится в git. При старте на Render сервер сам применит
миграции (`Migrate()`).

> Если миграций нет, сервер на Render создаст таблицы напрямую по модели, и сайт всё равно заработает.
> Но потом добавить миграции к уже созданной базе нельзя без её удаления — поэтому лучше сделать их сейчас.

Позже, при изменении модели: `dotnet ef migrations add ИмяМиграции` в папке `api` → коммит → пуш → Render применит.

## Шаг 6. Создать Angular-приложение и наложить файлы

Сам каркас Angular (`angular.json`, `package.json` …) создаёт `ng new`, а мои файлы кладутся поверх.

```bash
# из корня listings-app
ng new web --style=css --ssr=false --skip-git
```

На вопросы отвечайте Enter (значения по умолчанию). `--skip-git` — чтобы внутри не появился второй репозиторий.

Наложите файлы и удалите временную папку:

```bash
# macOS / Linux / Git Bash
cp -r web-overlay/. web/
rm -rf web-overlay
```
```powershell
# Windows PowerShell
Copy-Item web-overlay\* web\ -Recurse -Force
Remove-Item web-overlay -Recurse -Force
```

Проверьте: существует `web/scripts/set-env.mjs` и `web/src/environments/environment.ts`, а в `web/src/app/` —
папки `pages`, `services`, `interceptors` и др.

Запустите (сервер из шага 3 должен работать в другом терминале: `cd api; dotnet run`):

```bash
cd web
npm start
```

Откройте http://localhost:4200. **Проверьте руками:**

1. Список из 6 карточек, «Страница 1 из 2», кнопки «Вперёд/Назад», сортировка, выбор «6 / 12 / 24», кнопка «Обновить».
2. «Регистрация» → email и пароль (от 8 символов, с цифрой) → вы вошли, в шапке виден email.
3. «+ Добавить» → пустая форма → «Сохранить» → ошибки под полями; заголовок «Дом» → «Не короче 5 символов».
4. Корректная форма → переход на страницу объявления, видны кнопки «Редактировать», «Удалить» и поле «Фото объявления».
5. Загрузите картинку (jpg/png до 5 МБ) — фото появится на странице и в карточке на главной.
6. «Мои» → только ваши объявления. Выйдите и откройте `/listings/new` → переход на вход.
7. Откройте объявление №1 (из начальных данных): кнопок изменения нет — у него нет автора.

Тесты Angular и сборка:

```bash
npx ng test --watch=false
npm run build
cd ..
```

| Ошибка | Что делать |
|---|---|
| Ошибки компиляции в `listing-form-page` про `@angular/forms/signals` (`FormField`, `fieldTree`, `minLength`) | API signal forms менялся между версиями. Пришлите текст ошибки и вывод `ng version` — поправлю под вашу версию. |
| В браузере `blocked by CORS policy` | Сервер не запущен или порт не тот. Для локального запуска в `api/appsettings.json` уже разрешён `http://localhost:4200`. |
| `vi is not defined` в `ng test` | В `web/tsconfig.spec.json` в `types` добавьте `"vitest/globals"`. |

## Шаг 8. Деплой на Render

1. render.com → войдите через GitHub → **New + → Blueprint**.
2. Подключите GitHub-аккаунт, выберите репозиторий `listings-app` → Render найдёт `render.yaml` и покажет три ресурса:
   `listings-app-db` (PostgreSQL), `listings-app-api` (Docker), `listings-app-web` (Static Site).
3. Нажмите **Apply**. Первая сборка занимает 5–10 минут (сборка Docker-образа .NET — самая долгая).
   Статусы смотрите в Dashboard; у каждого сервиса есть вкладка **Logs**.

Когда `listings-app-api` станет **Live**, откройте его адрес + `/health` — должно быть `{"status":"ok"}`.

## Шаг 9. Сверить адреса (обязательно)

В `render.yaml` адреса сервисов заданы по умолчанию:

- API: `https://listings-app-api.onrender.com`
- Сайт: `https://listings-app-web.onrender.com`

Если имя оказалось занято, Render выдаст адрес с суффиксом. Откройте каждый сервис в Dashboard и посмотрите реальный URL
(под названием). Если он отличается:

1. Сервис **listings-app-web** → *Environment* → `API_URL` = реальный адрес API (без `/` в конце) → Save.
   Затем **Manual Deploy → Clear build cache & deploy** (адрес вшивается при сборке).
2. Сервис **listings-app-api** → *Environment* → `Cors__Origins__0` = реальный адрес сайта (без `/` в конце) → Save
   (сервис перезапустится сам).

Либо исправьте оба значения в `render.yaml`, сделайте `git commit` и `git push` — Render применит изменения.

## Ограничения бесплатного тарифа Render (важно знать к защите)

| Что | Следствие | Что делать |
|---|---|---|
| Бесплатный web-сервис «засыпает» через ~15 минут без запросов | Первый запрос после паузы идёт до минуты; сайт может показать «Сервер недоступен» | Откройте сайт за 2 минуты до показа, нажмите «Обновить» |
| Бесплатная PostgreSQL удаляется через 30 дней после создания | Данные пропадут | Перед защитой проверьте дату создания в Dashboard; при необходимости создайте базу заново или перейдите на платный план |
| Файловая система бесплатного сервиса временная | **Загруженные фото исчезают** при перезапуске и новом деплое. Сами объявления остаются | Для постоянных фото нужен платный Persistent Disk на `/app/wwwroot/uploads` либо внешнее хранилище (реализуется новой реализацией `IPhotoStorage` — урок 9 как раз про это) |

Актуальные условия тарифов проверяйте на render.com/pricing — они меняются.

## Частые проблемы при деплое

| Симптом | Причина и решение |
|---|---|
| Сборка API падает на `dotnet restore` | Откройте Logs, пришлите текст ошибки. Часто — версия пакета в `ListingsApi.csproj`. |
| API: `OptionsValidationException … Jwt:Key` | У сервиса нет переменной `Jwt__Key`. Dashboard → API → Environment: должна быть (создаётся Blueprint-ом, значение генерируется). Два подчёркивания — не опечатка. |
| API: ошибка подключения к базе / `password authentication failed` | Проверьте, что база и API в одном регионе (в `render.yaml` — `frankfurt`) и что `ConnectionStrings__Default` взята из базы `listings-app-db`. |
| `relation "Listings" does not exist` | Применена не та миграция. Удалите `api/Migrations`, повторите шаг 5, закоммитьте, и пересоздайте базу в Dashboard (Settings → удалить и применить Blueprint заново). |
| Сайт пустой, в консоли браузера `CORS` | `Cors__Origins__0` не совпадает с адресом сайта (шаг 9, п. 2). |
| Сайт: запросы идут на `localhost:5000` | `API_URL` не задан на момент сборки. Задайте и сделайте «Clear build cache & deploy» (шаг 9, п. 1). |
| Белая страница на `/listings/5` после F5 | Нет правила rewrite. Оно есть в `render.yaml` (`routes`); при ручной настройке сайта добавьте Rewrite `/*` → `/index.html`. |
| `Cannot POST /api/…` на сайте | Запрос идёт на адрес сайта, а не API — снова `API_URL`. |

## Если создавать сервисы вручную (без Blueprint)

1. **New → PostgreSQL** (Free, регион Frankfurt) → скопируйте *Internal Database URL*.
2. **New → Web Service** → репозиторий → Language: Docker → **Root Directory:** `api` → Region: Frankfurt → Free.
   Health Check Path: `/health`. Переменные: `Database__Provider=Postgres`, `ConnectionStrings__Default=<Internal URL>`,
   `Jwt__Key=<случайная строка ≥32>`, `Cors__Origins__0=<адрес сайта>`.
3. **New → Static Site** → репозиторий → Root Directory: `web` → Build Command:
   `npm ci && node scripts/set-env.mjs && npm run build` → Publish Directory: `dist/web/browser` →
   переменные `API_URL=<адрес API>`, `NODE_VERSION=22` → вкладка *Redirects/Rewrites*: `/*` → `/index.html` (Rewrite).
